## Project orientation

**TCGP Deck Builder** — React 19 + Vite 8 + TS + Tailwind 4 SPA deployed to GitHub Pages at https://thecryptocanuck.github.io/pokemon/. Mobile-first; the user runs it on Android Chrome.

### Where things live

- `src/App.tsx` — top-level state. Owns `useCollection` and `useDecks` hooks; routes the active tab to the right page component.
- `src/types/card.ts` — `Card`, `Deck`, `Tab`, `CardCategory` interfaces; helpers like `getCardId`, `isTrainerCard`, `matchesTypeFilter`, `getCardImageUrl`.
- `src/data/cards.ts` — fetches and merges two upstream JSONs:
  - **base**: `flibustier/pokemon-tcg-pocket-database/dist/cards.extra.json` (set, number, name, rarity, image, element, type, stage, health, retreatCost, weakness, evolvesFrom).
  - **rich**: `public/cards-rich.json` (attacks + abilities, generated by `scripts/fetch-rich-cards.mjs` from hugoburguete).
- `src/utils/`:
  - `deck-rules.ts` — hard validation (20-card, 2-copy, ≥1 Basic, ≤3 energy types).
  - `deck-scoring.ts` — 10 weighted heuristics, all returning `HeuristicResult`. Weights total 1.00. Hosts the `useDeckScoreTween` RAF hook used by the score ring.
  - `auto-build.ts` — archetype-aware greedy builder. Reuses `scoreDeck` as the objective.
  - `card-classifier.ts` — regex-based strategy detection on attack/ability text.
  - `haptics.ts` — `tap()` calls `navigator.vibrate(8)` (no-op when `prefers-reduced-motion`); only call on deck mutations + pin/unpin, never on filter taps or modal opens.
- `src/data/`:
  - `archetypes.ts` — slot/role budgets and `detectArchetype()`.
  - `trainer-roles.ts`, `synergy.ts`, `meta-decks.ts` — hand-curated lookup tables.
- `src/index.css` — Tailwind 4 `@theme` block defines 5 custom animations (`slide-up-fade`, `pop`, `sparkle`, `shimmer`, `count-pulse`) used as `animate-*` utilities. A single global `@media (prefers-reduced-motion: reduce)` rule collapses all transitions/animations to ~0 ms.
- `src/components/shared/CardModal.tsx` — renders attacks (cost pips + name + damage + effect) and abilities (purple "Ability" pill) when present on the Card. Used from both Collection grid taps AND deck-editor row taps.

### Conventions

- **Card type**: upstream uses `'pokemon' | 'supporter' | 'item' | 'tool' | 'Fossil'` — there is **no `'trainer'`**. Always go through `isTrainerCard(card)` instead of `card.type === 'trainer'`.
- **Card name encoding**: upstream uses curly apostrophes (e.g. `Professor’s Research`, U+2019), not ASCII. Hardcoded name lists must match.
- **Card IDs**: `${set}-${number}` (e.g. `A1-7`, `PROMO-A-1`). All sets uppercased; numbers parseInt-clean (no zero pad).
- **Anthropic Vision**: model ID is `claude-sonnet-4-6`. Browser-direct calls require the `anthropic-dangerous-direct-browser-access: true` header.
- **localStorage keys**: `tcgp-anthropic-key`, `tcgp-collection`, `tcgp-decks`. Don't break shape — existing users have data stored.
- **Pinned decks**: `Deck.pinnedAt?: string` (ISO timestamp; absent = unpinned). Sort: pinned first by `pinnedAt asc`, then unpinned by `createdAt desc`.
- **Mobile-first DeckEditor layout**: `DeckEditor.tsx` uses Tailwind `order-1 lg:order-2` on the deck panel and `order-2 lg:order-1` on the card browser. On phones (single column) the deck panel renders first so the user sees their deck immediately; on desktop the card browser sits on the left as you'd expect. Don't drop the `order-*` classes when refactoring.
- **Deck-row tap target**: each deck card row in `DeckEditor.tsx` is a `<div role="button" tabIndex={0}>` with onClick + Enter/Space handlers — NOT a `<button>`, because the inner `−` remove control is itself a `<button>` and nesting buttons is invalid HTML. The inner button uses `e.stopPropagation()` so it removes without opening the modal.
- **Score-tween + grade-pop hooks**: `src/components/deck-builder/DeckAnalysis.tsx` has two `setState`-in-`useEffect` blocks (one driving the RAF score tween, one re-keying the grade pill on grade change) wrapped in `eslint-disable react-hooks/set-state-in-effect`. Both are intentional — the React docs explicitly carve out "synchronizing state with an external system" (RAF / DOM remount) for this exact use case. Don't remove the disables.
- **Sparkle / pin-halo cleanup timers**: `DeckBuilderPage.tsx` holds short-lived `sparkleDeckId` and `justPinnedId` state with `useEffect` setTimeouts (~700–900 ms) that clear them. Always include the `clearTimeout` cleanup return so an unmount mid-animation doesn't leak.

### Refreshing rich card data

When a new TCGP set ships, run:

```bash
node scripts/fetch-rich-cards.mjs
```

This rewrites `public/cards-rich.json` from hugoburguete's main branch. Commit the result. The script is pure Node, no deps.

### Deploy

Push to `main` → `.github/workflows/deploy.yml` builds and publishes to GitHub Pages within ~1 minute. The user opens the public URL on Android Chrome to test (and may need a hard-refresh to bypass GitHub Pages' 10-minute HTML cache).

### Things that will trip you up

- **Sandbox TLS**: this dev environment can't always verify GitHub / jsDelivr certs. The card-DB fetch and image fetches will fail in headless browser dogfood. The user's actual phone is fine. Workaround for dogfood: copy `cards.extra.json` to `public/cards.dev.json` and temporarily point `CARDS_URL` at it (revert before committing).
- **Vite dev server**: bound to `0.0.0.0` (`server.host: true` in `vite.config.ts`) so the user's phone can reach `http://<dev-ip>:5173/pokemon/` over LAN.
- **gstack browse**: needs `CONTAINER=1` env var set so it adds `--no-sandbox` to Chromium when running as root.
