## Build Philosophy

1. **Every phase ships a working app.** The app must build, run, and pass smoke tests at the end of every phase. Never leave the codebase broken between phases.
2. **Local-first is sacred.** Hive remains the read source for all core features (breed ID, collection, gamification). Supabase augments — it never replaces — local storage. Every screen must have an offline fallback.
3. **Small, sequential tasks.** Each task is 15-45 minutes of focused coding agent work. Tasks are ordered so that later tasks can depend on earlier ones within the same phase.
4. **Trace everything to the PRD.** Every task references the functional requirement (FR-xxx) or user story (US-xxx) it satisfies. No orphan work.
5. **Test what matters.** Auth, sync, and data integrity get tests. UI polish does not. Prioritize correctness over coverage percentage.
6. **Ship before perfect.** Launch with v5.1 model (150 breeds) and local gamification. v6 model (294 breeds) and full social backend ship as post-launch updates. Users see "new features," not "delayed launch."
7. **Hybrid local/cloud is the architecture.** Writes go to Hive immediately, then queue for Supabase sync. Reads always come from Hive. Network failures are invisible to the user for core features.
8. **Respect the existing codebase.** 34 screens, 50+ services, 39 widgets already exist. Integrate, don't rewrite. New code plugs into existing Riverpod providers and go_router structure.
